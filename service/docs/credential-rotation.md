# 数据源凭据密钥轮换

数据源密码使用 AES-256-GCM，每行保存密文、96 位随机 IV 和密钥版本。轮换必须采用“先加、再迁、后删”的方式。

1. 生成新密钥：`openssl rand -base64 32`，将输出直接写入 Secret 管理系统，不复制到工单或日志。
2. 在配置中保留旧版本并新增新版本，例如 `keys.v1` 与 `keys.v2` 同时存在；将 `current-version` 改为 `v2`。先重启并确认新建/修改的数据行使用 `v2`。
3. 以 `rotation.enabled=true`、`rotation.dry-run=true`、`rotation.from-version=v1` 启动一次性实例。记录的只应是候选数和版本，不应包含 ID、密文或明文。
4. 核对数量后，以 `dry-run=false` 执行。任务按 `batch-size` 分批事务处理，并用旧版本条件更新，因此可安全重跑。
5. 查询/监控旧版本剩余数为 0；执行应用读写与连接测试，确认所有实例同时拥有新旧密钥期间均可解密。
6. 若验证失败，停止轮换实例，恢复 `current-version=v1`；由于旧密钥仍在，已迁移记录仍可由同时持有 `v2` 的版本读取。修复后再继续，不回写明文。
7. 所有实例完成发布、旧版本计数持续为 0 且备份保留期满足后，才从 Secret 和配置中移除 `v1`，然后滚动重启。

切勿在旧版本仍有记录、旧应用实例仍运行或回滚窗口未结束时删除旧密钥。
