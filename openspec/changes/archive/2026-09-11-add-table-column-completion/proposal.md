## Why

SQL 编辑器已经能补全当前库里的表名，但表名后输入 `.` 不会出现该表字段。现有补全只是把资源树已加载的名字摊成一张平铺词表，既不把 `.` 当触发字符，也不按限定符过滤，规格里写的「字段补全」实际不可用。

## What Changes

- 在 SQL 编辑器中，输入已加载表名后的 `.`（含引擎引号包裹的表名）时，补全该表字段。
- 字段按需通过现有 `table-detail` 拉取，并在当前连接/库的内存里缓存；不在展开库时预热全部表。
- 光标不在 `标识符.` 之后时，继续提供库名、表/视图名，以及已经缓存过的字段名；`表.` 之后只提供该表字段。
- 对不上已加载表名的限定符（别名、写错、子查询）不发元数据请求，也不假装有字段。
- 字符串和注释里的 `表.` 不触发字段补全或元数据请求；字段名插入复用引擎引用规则并转义内部引用符。
- 补全目录按连接/库标识持久化在编辑器页，切到历史或脚本侧栏、资源树卸载后仍能使用此前已加载的表清单。
- 刷新元数据或切换页签连接时立即失效字段缓存；失效前发出的异步响应不得重新写回旧字段。
- 本变更不解析 `FROM`/`JOIN` 别名，不新增后端 API，不预拉全库字段。

## Capabilities

### New Capabilities

- 无。本次只收紧现有 Monaco 元数据补全的行为，不引入新的能力域。

### Modified Capabilities

- `frontend-sql-editor-workbench`: 元数据补全从平铺词表改为：无限定符时提供已知库/表（及已缓存字段）；`表.` 时按需提供该表字段。

## Impact

- 前端：`SqlMonacoEditor` 补全提供者；带连接/库身份的资源目录快照及其页级持久化；带失效代次的 `table-detail` 缓存；限定符解析的可单测纯函数。
- 复用 `GET /api/v1/data-sources/{id}/table-detail`，不新增、不改后端契约。
- 刷新资源树时丢弃该连接上的字段缓存，避免 DDL 后继续提示旧列。
- SQL 执行、页签、结果网格、Copilot、资源树浏览本身保持现有行为。
