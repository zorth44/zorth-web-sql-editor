# Web SQL 编辑器前端开发说明书

> 工程建议名：`zorth-web-sql-editor`
>
> 状态：评审稿 v0.3
>
> 适用范围：仅支持 MySQL。第一阶段交付数据源管理，第二阶段交付 SQL 编辑器。
>
> 参考界面：Bytebase 3.20.x SQL Editor 的信息架构与交互方式

本次第一阶段实施范围仅为前端 `web/`。SQL 服务尚未实现，开发和自动化测试先严格按照后端说明书 §6、§8 的契约使用 Mock；不在本次工作中创建 `service/` 或修改授权服务。

## 1. 建设目标

建设一个独立部署的 Web SQL 编辑器站点，复用现有 `bddf-authorization-service` 的登录和 Token，允许用户管理并操作自己所属产品的数据源。

**用户能看见哪些数据源，由后端按该用户所属产品过滤后返回。** 前端只渲染接口结果，不在浏览器端再做产品权限过滤。

### 1.1 第一阶段：数据源管理

- 登录、退出和已有 Token 接入。
- 数据源列表、详情、新增、编辑、删除、测试连接。
- 按名称、主机过滤数据源列表；过滤由后端完成。
- 数据源创建时由后端自动归属当前用户所属产品；前端不展示或提交产品选择字段。

第一阶段登录后默认进入 `/data-sources`。不交付 SQL 编辑器工作台。

### 1.2 第二阶段：SQL 编辑器

- 查看数据库、表、字段、主键和索引。
- 使用 SQL 编辑器执行 MySQL 查询、DML 和 DDL。
- 查看表格结果、影响行数、执行耗时及错误信息。
- 将查询重新执行并导出为 CSV。
- 查看、搜索和重新打开当前用户的 SQL 执行历史。

第二阶段登录后默认进入 `/sql-editor`，顶栏保留数据源管理入口。

### 1.3 两阶段都不包含

- SQL 审批、危险操作拦截、SQL Review、数据脱敏和审计中心。
- 事务面板、跨请求手动提交或回滚。
- SQL 草稿、工作表分享、收藏和团队协作。
- 多数据库引擎、批量跨库查询和可视化执行计划。
- 表数据在线编辑。

## 4. 认证与会话

### 4.1 登录页

登录页对接授权服务当前实际使用的 LDAP 登录接口，而不是旧的 `POST /login`：

```http
POST /ldap/login
Content-Type: application/json
```

表单只展示用户名和密码。请求体字段为：

- `username`：EHR/LDAP 用户名。
- `password`：先按 UTF-8 做 Base64，再追加 12 位随机干扰字符串；该兼容编码只隔离在授权 API 适配层，不视为传输加密，生产环境必须使用 HTTPS。
- `productType`：不在页面展示，读取 `VITE_AUTH_PRODUCT_TYPE`，缺省为 `chinaBank`。
- `selectUserId`：仅在一个 LDAP 身份绑定多个本地账号、用户选定账号后再次登录时提交。
- “记住我”仅决定 SQL 编辑器 Token 存储在 `localStorage` 还是 `sessionStorage`，不保存用户名或密码，不改变服务端有效期。

授权服务使用 `AjaxResult` 包装响应，即使 HTTP 为 200，前端仍必须检查响应体 `code`：`200` 表示业务成功，其他值按 `msg` 展示失败。成功响应分为三种：

1. 含 `token`：登录完成，保存 Token 后调用 SQL 服务 `GET /api/v1/session`。
2. `needSelectAccount: true`：展示 `bindAccounts` 供用户选择，再携带 `selectUserId` 重试登录。
3. `needBind: true`：第一阶段不复制授权系统的账号绑定/创建流程；提示用户前往 `VITE_LEGACY_PORTAL_URL` 完成绑定后重试。

授权服务响应可能包含其遗留字段或 `ldapUser`。当前源码中的 `LdapUserVo` 公开了 `pwd`，部分登录分支又会把解码后的密码写入该对象；这是授权服务必须在生产联调前修复的问题（至少禁止序列化 `pwd`，并改为最小化响应 DTO）。本前端只读取上述必要字段，不持久化、缓存、打印或上报其他登录响应内容，但前端忽略该字段不能替代服务端修复。

登录成功后保存授权服务返回的顶层 `token`，随后调用 SQL 编辑器后端的 `GET /api/v1/session` 获取当前用户和产品上下文。Session 响应含 `expiresAt` 时，到期前不要假装仍已登录。

前端请求统一发送：

```http
Authorization: Bearer <token>
X-Request-Id: <uuid>
```

按 `capabilities` 显隐按钮：第一阶段至少处理 `DATA_SOURCE_MANAGE`；第二阶段再处理 `SQL_EXECUTE`、`SQL_EXPORT`、`HISTORY_READ`。没有对应能力时不要只靠藏按钮，接口失败仍要展示错误。

### 4.2 Token 存储

- 默认存入 `sessionStorage`。
- 用户勾选“记住我”时存入 `localStorage`。
- 每次登录成功先清除两处旧 Token，再只写入用户本次选择的 Storage，保证同一时刻只有一个有效副本。
- 不写入 Cookie，不在日志、埋点或错误上报中记录 Token。
- 收到 `401` 时清除 Token，记录当前安全路由并跳转 `/login`。
- 登录后只允许跳回站内相对路径，禁止任意外部 `redirect`，避免开放重定向。

### 4.3 老系统跳转接入

不能把 Token 放在查询参数中。推荐两种方式：

1. 老系统用新窗口打开 `/auth/bridge`，通过限定目标 Origin 的 `postMessage` 传递现有 Token。消息格式固定为 `{ type: "ZORTH_SQL_AUTH_TOKEN", version: 1, token: string }`。桥接页只接受 `event.source === window.opener` 且 `event.origin` 位于 `VITE_AUTH_BRIDGE_ALLOWED_ORIGINS` 白名单中的消息；成功后回复 `{ type: "ZORTH_SQL_AUTH_ACCEPTED", version: 1 }`，回复中不得包含 Token。
2. 若需要同窗口跳转，则由授权服务后续提供一次性 SSO Ticket，编辑器用 Ticket 换取原有 Token。Ticket 单次使用、60 秒过期。

桥接页收到 Token 后仍必须调用 `GET /api/v1/session` 验证，不能仅凭前端存在 Token 判定登录成功。

本次前端只实现桥接接收方。老系统打开新窗口并发送上述消息的改造属于外部依赖，不在本次前端仓库范围内。

### 4.4 退出

退出时调用授权服务 `POST /logout` 并携带 Bearer Token。当前授权服务返回 `{ "code": 200, "msg": "退出成功" }`。随后清除两种 Storage 中的 Token、编辑器临时状态和请求缓存；若授权服务退出失败，也要清除本地会话。

## 6. 数据源管理（第一阶段）

### 6.1 可见性

- 列表接口已经按当前用户所属产品过滤。前端不要再按产品裁剪，也不要把“当前产品”当成可切换的过滤条件。
- 每条数据源只归属一个产品，不存在共享或跨产品绑定。不同产品即使配置相同的数据库实例，也会形成不同的数据源 ID。
- 手工把 URL 改成其他数据源 ID 时，后端返回 `404 DATA_SOURCE_NOT_FOUND`（无权限与不存在不区分）。前端展示“数据源不存在或已不可见”，不要写成“没有权限访问该数据源”。

### 6.2 数据源列表

显示字段：

- 名称。
- 类型，固定为 MySQL。
- 主机和端口。
- 默认数据库，可为空。
- 最近一次测试状态和时间。
- 更新时间、更新人（使用 `updatedByName` 快照，不要展示原始用户 ID）。
- 操作：测试、编辑、删除；第二阶段再提供“进入编辑器”。

列表过滤：把用户输入作为 `keyword` 传给后端。后端在名称和主机上做模糊匹配。前端不要自己对未加载完的分页结果做跨页过滤。

列表固定按 `updatedAt DESC, id DESC` 排序并使用游标分页。第一阶段使用“上一页/下一页”，前端保存已经访问过的游标栈，不实现数字页码随机跳转。

前端只会收到脱敏后的用户名及 `passwordConfigured`，永远不展示数据库密码。

### 6.3 新增/编辑表单

编辑页加载 `GET /api/v1/data-sources/{id}`。`404` 时回到列表并提示不可见。

字段：

| 字段       | 必填     | 规则                                                                        |
| ---------- | -------- | --------------------------------------------------------------------------- |
| 数据源名称 | 是       | 1–100 字符；允许重名，数据源仅以 ID 唯一标识                                |
| 数据库类型 | 是       | 固定 MySQL                                                                  |
| Host       | 是       | 域名、IPv4 或 IPv6，不带协议；IPv6 原样提交，由后端生成 JDBC URL 时加方括号 |
| Port       | 是       | 默认 3306，1–65535                                                          |
| 用户名     | 是       | 1–128 字符                                                                  |
| 密码       | 新增必填 | 编辑时留空表示保持原密码                                                    |
| 默认数据库 | 否       | 第一阶段只提供手工输入；第二阶段接入数据库元数据后再升级为可选择            |
| JDBC 参数  | 否       | 只展示后端白名单键；不允许完整 JDBC URL，也不允许填写 SSL、user、password   |
| SSL 模式   | 是       | `DISABLED`、`PREFERRED`、`REQUIRED`。第一阶段不校验证书和主机名             |
| 连接超时   | 是       | 默认 10 秒，1–30 秒。测试连接等待时间与此相同，硬上限 30 秒                 |
| 描述       | 否       | 最大 500 字符                                                               |

保存前允许点击“测试连接”。测试请求带上当前表单的 `connectTimeoutSeconds`，不要另用 10 秒超时。新增和编辑保存成功后返回列表并刷新缓存。

编辑时测试当前表单调用 `POST /api/v1/data-sources/{id}:test` 并提交当前连接字段；密码为空时由后端复用已保存密码。该测试不保存表单，也不更新已保存配置的最近测试状态。列表页直接测试已保存配置时调用同一路径但不提交请求体，并更新最近测试状态。

### 6.4 删除

- 二次确认框显示数据源名称，并要求用户输入完全相同的名称后才能提交。名称可能重复，实际删除目标始终以数据源 ID 为准。
- 删除只影响当前产品下该数据源 ID，不影响其他产品独立创建的配置。
- 后端返回 `409 DATA_SOURCE_IN_USE` 时展示正在执行的任务数量并禁止删除（第二阶段才会出现）。

## 7. SQL 编辑器工作台（第二阶段）

### 7.1 当前连接

当前连接由左侧资源树选择，并绑定到当前编辑器页签。页签展示所属数据源和数据库；工具栏不再提供全局数据源/数据库下拉。

选择状态写入 URL，例如：

```text
/sql-editor?dataSourceId=ds_123&database=demo
```

URL 仅包含非敏感 ID 和数据库名。打开 URL 时后端重新鉴权，不能相信 URL 中的产品或数据源信息。无权限的数据源 ID 按 404 处理。

### 7.2 左侧资源面板

“数据库”面板包含：

- 数据库搜索框。
- 数据库树。
- 展开数据库后显示“表”和“视图”分组。
- 表/视图过滤框。
- 展开表后显示字段；点击表打开详情抽屉，展示字段、主键和索引。

资源按需加载：选择数据源时加载数据库，展开数据库时加载表，展开表时加载字段。切换数据源后清空旧元数据缓存。

默认隐藏系统库只影响导航树。用户仍可在编辑器里查询 `information_schema` 等对象，最终可见性以 MySQL 账号为准。

交互：

- 双击表名向编辑器插入带反引号的表名。
- 表右键提供“复制名称”“生成 SELECT 前 100 行”“查看结构”。
- 字段显示字段名、类型、NULL、主键标识。
- 刷新按钮只刷新当前层级。

### 7.3 SQL 页签

- 默认创建一个 `Query 1` 页签。
- 页签内容只保存在内存；可选恢复缓存只能用 `sessionStorage`，不得写入 `localStorage`，不得存放 Token、密码或查询结果。限制总容量，登出时清空。第一阶段不做页签恢复。
- 关闭非空页签需确认。
- 页面异常刷新后可从 `sessionStorage` 恢复最近未提交 SQL；登出或 `401` 时清空。
- 页签必须绑定当前数据源和数据库，并在页签上展示该绑定（查询名 + 数据源 / 数据库）。切换连接后新建页签，不静默改变旧页签连接。
- 当前页签用对比背景和底边品牌色指示条与未选中页签区分，不能只靠焦点描边。

### 7.4 Monaco 功能

第二阶段支持：

- MySQL 语法高亮和括号匹配。
- 查找、替换、撤销、重做。
- SQL 格式化。
- 基于当前数据库元数据的库、表、字段补全。
- `Cmd/Ctrl + Enter` 执行选区；没有选区时执行光标所在语句。
- `Cmd/Ctrl + Shift + Enter` 执行编辑器全部文本，若包含多条语句则阻止并提示“暂不支持批量执行”。
- `Cmd/Ctrl + S` 不保存到后端，显示“工作表保存暂未开放”，避免误导用户。

每次请求只执行一条 JDBC Statement。前端做尽力切分（正确处理字符串和注释里的分号）；后端用同一规则做权威校验。无法可靠识别时由后端返回 `MULTI_STATEMENT_NOT_SUPPORTED`。存储过程、触发器等内部含分隔符的脚本不作为验收范围。

`executionId` 由前端在点击运行时生成 UUID。同一页签禁止重复提交；网络层对执行和导出绝不自动重试，因此不要用同一个 ID 重放请求。

### 7.5 执行交互

点击“运行”后：

1. 检查已选数据源和非空 SQL。`SHOW DATABASES`、`SELECT 1` 等可不选数据库；访问表对象的语句必须已选数据库，否则前端拦截。
2. 创建结果页签并进入运行状态。
3. 调用 `POST /api/v1/sql/executions`。
4. 查询类语句显示表格；DML/DDL 显示消息卡片。
5. 不论成功失败，后端都写入执行历史。

运行中：

- 运行按钮变为“停止”。
- 点击停止调用取消接口。
- 页面关闭或离开时用 `AbortSignal` 取消进行中的 fetch；后端在 HTTP 断开时停止 Statement。
- 禁止同一编辑器页签重复提交，但允许不同页签并行；前端最多允许 3 个并行执行。

成功消息示例：

- 查询：`返回 1,000 行（已达到上限），耗时 328 ms`。
- DML：`执行成功，影响 42 行，耗时 97 ms`。
- DDL：`执行成功，耗时 215 ms`。

错误展示：

- 保留 MySQL 错误码、SQLState 和后端返回的安全错误信息。
- 若后端返回行列位置，在 Monaco 中标出。
- 不显示 JDBC URL、数据库密码、后端堆栈和内部网络细节。
- `404 DATA_SOURCE_NOT_FOUND` 提示数据源不存在或已不可见。
- `409 EXECUTION_ID_CONFLICT` 提示请重新运行，不要复用旧执行 ID。
- `422` 展示 SQL 错误；`429` 提示并发超限；`504` 提示执行超时。

### 7.6 查询结果

结果表格视觉与列操作参考 CloudBeaver 的结果网格，不复制其品牌资源。表格支持：

- 电子表格式细网格、固定表头、行号列、横向滚动和行虚拟化。
- 表头显示数据类型标记：数值 `123`、文本 `A-Z`，以及日期、二进制等简写。
- 选中行使用浅底，当前单元格使用深色内边框；当前单元格右侧提供操作菜单。
- 单元格菜单与右键菜单：在值面板中显示、复制单元格/整行、排序、筛选、固定列、取消所有固定。
- 列宽可拖动；固定列停留在行号右侧。
- 排序和筛选只作用于已返回结果，不重新查询数据库。
- 单元格复制、整行复制、复制当前结果；`⌘/Ctrl + C` 复制当前单元格。
- NULL 使用斜体 `NULL`，空字符串显示为空并提供 tooltip 区分。
- 超长文本折叠预览；双击或“在值面板中显示”在右侧值面板打开全文。
- `BLOB/BINARY` 显示类型和字节数，不预览原始二进制。后端单元格形如 `{ "binary": true, "size": 1234, "base64": null }`。
- 底栏提供下次运行生效的返回行数上限、返回行数/截断/耗时，以及查询结果的 CSV 导出。
- 显示返回行数、影响行数、执行耗时、是否截断。

`jdbcType` 和 `typeName` 都是字符串：`jdbcType` 用 JDBC `Types` 名称（如 `BIGINT`），`typeName` 用数据库原生名。不要把它们当成数字。

结果类型定义：

```ts
type SqlExecutionResult =
  | {
      kind: "RESULT_SET";
      executionId: string;
      columns: Array<{
        name: string;
        label: string;
        jdbcType: string;
        typeName: string;
      }>;
      rows: Array<Array<unknown>>;
      rowCount: number;
      truncated: boolean;
      durationMs: number;
    }
  | {
      kind: "UPDATE_COUNT" | "DDL";
      executionId: string;
      affectedRows: number | null;
      durationMs: number;
      message: string;
    };
```

JavaScript 无法无损表示超过 53 位有效范围的整数。后端必须将 `BIGINT`、`DECIMAL` 等可能丢失精度的值以字符串返回，前端不得强制转为 `number`。

## 8. CSV 导出（第二阶段）

- 仅查询结果显示导出按钮，放在结果网格底栏；DML/DDL 不显示。
- 点击导出把当前成功查询的 `executionId` 传给 `POST /api/v1/sql/exports`，后端从该用户历史中读取原 SQL 并重新执行，然后流式返回 CSV；前端不再次提交可替换的 SQL 文本。
- 前端提示“导出会重新执行当前 SQL，数据可能与屏幕结果不同”。这一行为与最新 Bytebase 一致。
- 文件名：`<dataSource>-<database>-<yyyyMMdd-HHmmss>.csv`。
- CSV 编码 UTF-8 with BOM，便于中文版 Excel 打开。
- 导出请求沿用后端查询行数、结果体积和超时上限；可把 `rowLimit` 提到硬上限。
- 第一阶段浏览器使用 `fetch` + `AbortSignal` + Blob 下载。100 MB 上限对浏览器内存同样生效，不要再把 Blob 转成字符串。
- 下载中的导出允许取消。

## 9. 执行历史（第二阶段）

历史面板只展示当前用户自己的记录，支持：

- 按 SQL 关键字搜索。
- 按数据源、数据库、状态、语句类型筛选。
- 时间倒序和游标分页。
- 展示语句摘要、状态、连接、执行时间、耗时和影响/返回行数。
- 点击历史在新页签恢复原 SQL 和连接；连接已删除或已无权限时仅恢复 SQL，并要求重新选择连接。
- 支持复制 SQL，不提供删除和修改历史。

历史是产品功能记录，不实现危险 SQL 审计、审批或告警。

第一阶段先实现 `client`、`session`、`data-sources` 以及数据源相关页面。`metadata`、`executions`、`history` 和编辑器组件放在第二阶段。

后端未实现期间，MSW handler 必须复用同一套 TypeScript 请求/响应类型，覆盖正常、空列表、连接失败、401、404、版本冲突和删除占用场景。Mock 不得产生第二套字段命名或宽松兼容逻辑；生产入口不得注册 Service Worker。

API 返回统一处理：

```ts
interface ApiError {
  requestId: string;
  code: string;
  message: string;
  details?: Record<string, unknown>;
}
```

重试规则：

- GET 元数据和 GET 数据源详情遇到网络错误最多自动重试一次。
- 新增、修改、删除、测试连接、SQL 执行和导出绝不自动重试。
- `401` 清理登录态。
- 数据源 `404` 展示不可见，不要当成可重试的权限错误。
- `409` 显示资源冲突（乐观锁、执行 ID 冲突、数据源使用中）。
- `422` / `429` / `504` 按执行错误、并发超限、超时展示。

## 11. 缓存与刷新

- Session：5 分钟 stale，窗口重新聚焦时验证；以服务端 `expiresAt` 和 401 为准，前端缓存不延长 Token。
- 数据源列表：30 秒 stale，新增、修改、删除以及“测试已保存配置”完成后立即失效。
- 数据源详情：编辑页按 ID 拉取，保存或测试已保存配置后失效；测试未保存表单不失效。
- 数据库列表：60 秒 stale。
- 表和字段元数据：5 分钟 stale，DDL 成功后使当前数据库元数据失效并刷新。
- 历史列表：执行结束后立即使第一页失效。
- Token、数据库密码和完整结果集不得进入持久化 Query Cache。

## 12. 可访问性与浏览器

- 支持最新版 Chrome 和 Edge；Safari 作为兼容目标但不作为强验收浏览器。
- 所有按钮提供文字或 `aria-label`。
- 键盘可操作资源树、页签、运行和结果表格。
- 颜色不是状态的唯一表达方式。
- 编辑器与结果区域须有明确焦点边界。

## 13. 测试与验收

### 13.1 单元/组件测试

第一阶段：

- Token 存储、401 清理及安全重定向。
- 数据源表单校验、允许名称重复、编辑密码留空语义。
- 请求错误映射、不可重试请求不重放。

第二阶段：

- SQL 选区和当前语句提取。
- BIGINT、DECIMAL、NULL、空字符串和二进制展示。
- DDL 成功后元数据缓存失效。

### 13.2 E2E 核心流程

第一阶段：

1. 登录后进入数据源管理。
2. 新增数据源并测试连接；请求不包含产品 ID，后端自动归属当前产品。
3. 编辑页从详情接口回填，密码不回显。
4. 产品 A 用户不能通过手工修改 URL 打开产品 B 的数据源（表现为 404）。
5. 数据源密码在列表、详情、日志和浏览器缓存中均不可见。

第二阶段：

6. 搜索数据库和表，查看字段与索引。
7. 执行 SELECT 并查看结果。
8. 执行 INSERT、UPDATE、DELETE 和常见 DDL 并显示影响信息。
9. 执行失败后显示 MySQL 错误，历史中存在失败记录。
10. 导出 CSV，验证中文、逗号、引号、换行、NULL 和公式前缀。
11. 搜索历史并重新打开 SQL。
12. 停止正在执行的查询后，运行按钮恢复可用。

## 14. 待评审决策

以下按推荐默认值编写，评审时可以调整：

- 先交付数据源管理，再交付 SQL 编辑器。
- 前端使用 Vue 3 + TypeScript，而不是 React。
- 每条数据源只归属创建者当前所属产品；前端不展示产品选择，也不提交产品 ID。
- 数据源名称允许重复，前后端只能用数据源 ID 标识记录。
- 登录 Token 默认使用 `sessionStorage`；勾选“记住我”才使用 `localStorage`。
- 老系统新窗口跳转采用 `postMessage`，同窗口跳转以后增加一次性 SSO Ticket。
- 第二阶段一次只执行一条语句；用户可同时运行最多 3 个语句。
- 导出会重新执行 SQL，而不是导出屏幕内存中的结果。
